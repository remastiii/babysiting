COMPONENTS / REUSE
There are no partials, components, or templates. The header and footer are
copy-pasted into every single file. This is the biggest structural technical debt.

CSS STRUCTURE
A single style.css (~1,300 lines) shared across all pages (blog pages use ../style.css).
Flat stylesheet, no preprocessor (no SCSS). Organization: Reset -> Header -> Hero ->
Cards -> Services/Prices -> Form -> Modal -> Footer -> Language Dropdown -> Animations
-> Blog-specific styles. Multiple overlapping responsive breakpoints (max-width: 768px
appears in several separate blocks).

JAVASCRIPT STRUCTURE
- script.js — Main page only. Handles: scroll animation (two separate IntersectionObserver
  instances with overlapping logic), contact form validation + Formspree submission,
  modal open/close, smooth scroll for hash links, hamburger toggle.
  NOTE: language dropdown on the main page is CSS :hover only — no JS click handler.
- blog/blog.js — Blog pages only. Handles: hamburger toggle, scroll animation, language
  dropdown click handler (more robust than the main page approach).

ASSETS / IMAGES
- hero-site.webp — Hero background (CSS background-image)
- babyguardmix.png — OG/Twitter share image (1200x630)
- Logo.png — Referenced in schema only
- logoorange.png — Referenced in blog schema JSON-LD
- Favicon set (.ico, .svg, .png x4, Apple touch) — inconsistently enabled (see Section 5)

There are ZERO <img> tags anywhere in the site. All images are either CSS backgrounds
or in meta/schema only.

ROUTING / NAVIGATION
Flat file routing with hash-based in-page navigation on the homepage. Blog pages use
full absolute paths (/#usluge). No JS router.
Navigation items: O nama, Usluge, Cenovnik, Hoteli, Kontakt, Zaposljavanje, FAQ, Blog.
The Recenzije (reviews) section has id="recenzije" but is NOT linked in the nav.

FORMS
Single contact form (id="contactForm") at #kontakt on each language page.
Honeypot anti-spam field (name="_gotcha", hidden).
Submitted via fetch to Formspree endpoint: https://formspree.io/f/mrbyrdrj
On success: fires Google Ads conversion, shows success modal.

WHATSAPP FUNCTIONALITY
Three distinct WhatsApp touchpoints:
1. Floating button (fixed, bottom-right, green, animated) — fires Google Ads conversion + opens WA with pre-filled message
2. Hero CTA button ("Kontaktirajte nas") — same behavior
3. Hotel section CTA — separate pre-filled message for hotel partnership
4. Footer icon — plain wa.me link, no conversion tracking

5. TECHNICAL QUALITY
================================================================

CONSOLE / RUNTIME ISSUES (visible from code)
- Two separate IntersectionObserver instances in script.js observe overlapping elements.
  First observes all <section> tags, second observes .animated-section. Double class-add
  (visible + animate-in) but no runtime crash.
- body.loading pattern: <body class="loading"> hides everything via CSS. Class removed only
  on window.load. If JS fails, THE ENTIRE PAGE IS INVISIBLE. No <noscript> fallback.
- osveziAktivnuSekciju function is fully commented out — dead code (~30 lines left in).
- Facebook social link is a large commented-out block in the footer.

RESPONSIVE ISSUES
- Language dropdown on index.html, en.html, ru.html opens on CSS :hover ONLY.
  On touch/tablet devices this doesn't work. blog.js uses click — main script.js does not.
- Hero H1 at 768px has conflicting rules in two separate media query blocks.
  (40px in one block, 24px in another — last one wins, fragile).

BROKEN LINKS
- Logo href="#" on index.html and en.html — does not navigate to root.

UNNECESSARY DEPENDENCIES
- Google Fonts (Poppins) loaded via @import inside CSS — render-blocking, delays first paint.
  Should use <link rel="preconnect"> + <link rel="stylesheet"> in <head>.
- Google Ads gtag loaded async at top of <head> on every page including blog posts.

PERFORMANCE CONCERNS
- @import url(...) for Google Fonts inside CSS is the worst loading method for performance.
- No lazy loading (no <img> tags currently, so not applicable).
- hero-site.webp as CSS background — browser discovers it late, no fetchpriority="high" possible.
- Inline <style> block for WhatsApp float is inside <body> near closing tag.

ACCESSIBILITY ISSUES
- Floating WhatsApp button has no aria-label — MEDIUM
- Contact form section (#kontakt) has no heading — screen readers lose context — MEDIUM
- body.loading hides all content from screen readers until JS fires — MEDIUM
- No "skip to content" link — LOW
- Color contrast: #e74c3c red on white — passes AA for large text, borderline for small — LOW
- Emoji in logo text ("BabyGuard") read aloud by screen readers — LOW

FAVICON INCONSISTENCY
- index.html: all favicon tags COMMENTED OUT except <link rel="icon" href="/icon.ico">
- en.html: FULL favicon set correctly declared
- ru.html: only <link rel="icon" href="/icon.ico">
- <link rel="manifest"> commented out on index.html — PWA disabled on primary page
